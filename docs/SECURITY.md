# 보안 · 공격 막기 설계

경쟁 게임사나 악의적인 사용자가 이 도구를 망가뜨리려 할 때 무엇을 노리고, 무엇이 막고, 무엇이 남는지. 시험으로 확인한 것은 시험 이름을 적었다.

## 바깥에서 닿는 곳

```
인터넷 ──▶ 디스코드 ──(봇이 먼저 연결)──▶ 서버          들어오는 문 없음
인터넷 ──▶ 슬랙     ──(소켓 모드: 서버가 먼저 연결)──▶ 서버   들어오는 문 없음 (결정 40)
인터넷 ──▶ Cloudflare 터널 ──▶ nginx ──▶ 게임 오류 받는 곳만   (결정 37)
내 컴퓨터(127.0.0.1) ──▶ 제보 등록·이슈 조회·관리 API
```

서버 주소가 인터넷에 열려 있지 않다. 디스코드·슬랙은 서버가 바깥으로 연결해 받는다. 그래서 서버를 직접 두드리는 디도스는 닿을 곳이 없다. 게임 오류 받는 곳 하나만 공개 주소가 필요하고, 그것도 Cloudflare 터널 뒤라 집 IP 가 드러나지 않는다.

## 공격별

| 공격 | 노리는 것 | 막는 것 | 확인 |
|---|---|---|---|
| 한 사람 도배 | 제보 수를 부풀려 먼저 볼 순서 흔들기, 채널 마비 | 신뢰 등급별 10분 한도(아래). 막힌 뒤 답장은 10분에 한 번만(봇 답장으로 채널이 두 배로 차지 않게) | `DiscordReportHandlerTest` 막힌_사람에게는_한_번만_답한다 |
| 새 계정 무더기 · 묵혀 둔 계정 | 계정을 여럿 만들거나 미리 만들어 두었다가 한꺼번에 쓰기 | 등급을 계정 나이가 아니라 실적으로 매긴다. 오래된 계정도 실적이 없으면 새 사람 | `IntakeGuardTest` 새_사람은_10분에_3건_오래된_계정이어도_같다 |
| 게임 하나에 폭주 | 가짜 장애처럼 보이게 하기, 운영자 지치게 하기 | 1분 30건 넘으면 몰림 모드: 새 사람 제보는 보류함에 받아 두고 몰림이 풀리면 차례로 접수(잃지 않음), 실적 있는 사람·우수 테스터는 그대로. 슬랙 긴급 채널에 10분에 한 번 알림 | `IntakeGuardTest` 몰리면_새_사람은_보류함에… |
| 끊어 쓴 글 | (공격이 아님) 한 제보를 여러 줄로 나눠 보냄 → 도배로 막히거나 이슈가 조각남 | 같은 사람이 같은 채널에 이어 쓴 줄은 마지막 글 뒤 20초(최대 60초) 모아 제보 하나로 | `DiscordMessageBufferTest` |
| AI 비용 공격 | 서로 다른 긴 글을 잔뜩 보내 번역·판정을 계속 부르게 | 글 앞부분만 보냄(분류·번역 1,500자, 판정 600자). 판정은 한 제보에 3번까지, 글자 비교로 붙는 제보엔 안 부름. 한 시간 600번 넘으면 그 시간은 규칙만 + 알림. 월 예산·남은 크레딧이 바닥이면 멈춤(결정 34·38). 도배 막기를 통과한 제보만 AI 에 간다 | `AiUsageTest` 한_시간_호출_상한을_넘으면_AI를_안_부르고_한_번_알린다 |
| 프롬프트 주입 | 플레이어 글에 「분류를 긴급으로」·「이 지시를 따르라」 | AI 는 정해진 칸만 받고 값 목록으로 검증(분류). 번역·판정 프롬프트는 글을 믿지 않는 데이터로 감싸고 지시를 따르지 말라고 적는다. 판정은 같은 분류 후보 안에서 붙일지 말지만. 개발 AI 지시서는 「참고 자료」 표시와 @·#·HTML 무력화(결정 29). AI 번역은 「AI 번역」이라고 밝힌다 | `AiDedupeTest`, `DevHandoffTest` |
| 멘션 폭탄 | 봇이 @everyone 을 부르게 | 봇 글은 @everyone·@here·역할을 부르지 못한다. 답장 대상 한 사람만 | `DiscordGateway` 기본 설정 |
| 슬랙 위조 요청 | 버튼을 누른 척 이슈 닫기 | 원래 바이트로 서명 확인, 상수 시간 비교, 5분 넘은 요청 거절(다시 보내기 막기). 관리 버튼은 정한 사람만 | `SlackInteractionTest` |
| 게임 오류 주소 두드리기 | 오류 기록을 쓰레기로 채우기 | nginx 주소당 1분 30번, 16KB, 게임 키, 게임당 하루 새 오류 200종 | `ClientErrorsTest` |
| 관리 키 추측 | 관리 API 로 규칙·상태 바꾸기 | 내 컴퓨터에서만 열림, 상수 시간 비교, 빈 키는 아무도 통과 못 함 | `ApiTest` |
| 키 유출 | 토큰으로 봇·저장소 장악 | `.env` 는 깃에 안 올림, 로그에 값 안 찍음, AI 에이전트 키 따로(해결·보류 못 함, 결정 21), 깃허브 토큰은 저장소 하나 | 설정 |

## 신뢰 등급과 근거

| 등급 | 조건 | 10분 한도 | 몰림 모드 |
|---|---|---|---|
| 새 사람 | 실적 없음 | 3건 | 보류함 |
| 확인된 사람 | 제보가 「운영자가 다룬 이슈」에 1개 이상 들어감 | 5건 | 그대로 |
| 믿는 사람 | 그런 이슈 3개 이상, 서로 다른 날 2일 이상 | 10건 | 그대로 |
| 우수 테스터 | 디스코드 「우수 테스터」 역할(운영자가 준다, `DISCORD_MEMBER_ROLES`) | 10건 | 그대로 |
| 운영진 | 운영진 역할(`DISCORD_STAFF_ROLES`) | 없음 | 그대로 |

「운영자가 다룬 이슈」 = 사람이 작업 중·QA 확인 대기·해결로 옮긴 이슈. 이슈가 생긴 것만으로는 실적이 아니다(누구나 만들 수 있으므로). 모든 계정에 같은 규칙을 쓰고 예외는 역할뿐이다.

**계정 나이를 뺀 이유.** 처음(결정 43)에는 가입 7일·30일로 나눴는데 근거 없는 숫자였다. 찾아본 기준도 제각각이다. 디스코드 서버 인증 「높음」은 가입 5분·서버 참여 10분만 본다([Discord 고객센터](https://support.discord.com/hc/en-us/articles/216679607)). 레이드 막기 봇은 1주·1달·3달 중 운영자가 고르게 둔다([ProBot](https://docs.probot.io/docs/modules/anti_raid)). 정해진 값이 없고, 무엇보다 미리 만들어 묵혀 둔 계정은 어떤 나이 기준도 그냥 통과한다.

**실적으로 매긴 근거.** 오래 운영된 커뮤니티 도구 Discourse 는 신뢰 등급을 가입 기간이 아니라 활동으로 올린다. 2단계는 「서로 다른 날 15일 방문, 글 100개 읽기, 좋아요 주고받기」 같은 조건이다([Discourse 신뢰 등급](https://meta.discourse.org/t/discourse-trust-levels-a-detailed-explanation/396792)). 여기서 「활동」에 해당하는 건 「운영자가 실제로 다룬 제보」다. 이건 공격자가 혼자 만들 수 없다(운영자가 그 이슈를 움직여야 하므로). 「서로 다른 날」 조건도 Discourse 처럼 하루에 몰아서 등급을 올리지 못하게 둔 것이다.

**숫자 3·5·10 은 시작 값이다.** 정상 플레이어가 10분에 서로 다른 버그를 3건 넘게 올리는 일은 드물고, 끊어 쓴 줄은 이제 한 건으로 센다. 실제 운영에서 막힌 건수를 보고 고친다. 모두 설정값이라 코드를 바꾸지 않고 조정한다.

## 남는 위험

- **실적을 쌓은 뒤 쓰는 계정.** 진짜 버그를 몇 번 제보해 「확인된 사람」이 된 뒤 도배하면 10분 5건까지는 통과한다. 몰림 모드도 통과한다. 이때는 슬랙 몰림 알림을 보고 사람이 판단한다. 실적을 쌓는 데 운영자 손이 들어가야 해서 계정 나이보다 훨씬 비싸다.
- **진짜 새 플레이어의 제보가 늦어짐.** 몰림 모드에서 처음 제보한 사람은 보류함을 거쳐 몰림이 풀린 뒤 접수된다. 잃지는 않는다.
- **같은 사람 제보가 제보 수에 여러 번 셈.** 10분 5건까지는 같은 사람도 센다. 「서로 다른 사람 수」를 따로 보이는 게 다음 단계다.
- **AI 판정을 속여 엉뚱한 이슈에 붙이기.** 같은 분류 후보 안에서만 붙고, 슬랙 [떼어내기]로 되돌린다. 잃는 제보는 없다.
- **게임 오류 주소 대량 공격.** Cloudflare 의 기본 보호와 nginx 제한까지다. 고정 주소로 옮길 때(클라우드 이전) Cloudflare 규칙을 따로 건다.

## 디스코드 서버에서 함께 켤 것 (운영 권장)

- 서버 인증 수준 「중간」 이상(가입 5분 뒤부터 글쓰기).
- 제보 채널 슬로 모드 30초.
- AutoMod: 링크·대량 멘션 차단.

이 도구의 막기는 디스코드 설정이 놓친 것을 한 번 더 거르는 자리다.
