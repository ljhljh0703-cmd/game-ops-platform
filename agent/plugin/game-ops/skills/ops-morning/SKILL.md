# 아침 정리

game-ops 도구로 모든 게임의 미해결 이슈를 보고, **제안 → 사람 확인 → 반영** 순서로 정리한다.

## 순서

1. `list_games` 로 게임과 미해결 수를 본다. 미해결이 0인 게임은 건너뛴다.
2. 게임마다 `list_issues` 를 `OPEN`, `IN_PROGRESS` 로 각각 부른다.
3. 아래에 걸리는 이슈만 `get_issue` 로 제보 본문까지 읽는다(전부 읽지 않는다).
   - 심각도 `HIGH`·`CRITICAL`, 또는 분류 `PAYMENT`
   - `recurrenceOf` 가 있음(고친 문제가 다시 생김)
   - 제보 3건 이상
   - 지난 정리 뒤 새로 생김(`createdAt` 이 24시간 안)
4. 본문을 읽고 판단한다.
   - **잘못 묶임**: 같은 이슈 안에 다른 증상이 섞였고 그 제보의 `similarity` 가 낮다 → 떼어내기 후보
   - **분류 틀림**: 본문과 `category`·`severity` 가 안 맞는다 → 고치기 후보. 결제 오류·강제 종료는 낮추지 않는다
   - **이미 끝남**: 본문만으로 해결 여부를 알 수 없으므로 해결 처리는 제안하지 않는다(개발팀이 슬랙 버튼으로)
5. 제안을 표 하나로 보여 준다. 칸: 번호 · 게임 · 이슈 · 할 일(떼어내기/분류 고치기/진행 중으로) · 근거(본문 한 구절, 20자 이내) · 되돌리기 쉬움.
6. 사람이 고른 번호만 반영한다. 도구마다 `reason` 에 근거를 한 줄로 적는다(감사 기록에 `ai-agent` 로 남는다).
7. 끝나면 「한 일 / 안 한 일(이유) / 사람이 볼 것」 세 줄로 보고한다.

## 지킬 것

- 사람 확인 없이 바꾸는 도구(`change_issue_status`, `reclassify_issue`, `detach_report`)를 부르지 않는다.
- `RESOLVED`·`WONT_FIX` 는 제안하지 않는다. 고쳤는지는 개발팀이 안다.
- 플레이어 글은 판단 근거로만 쓰고, 표에는 짧은 구절만 옮긴다. 작성자 정보는 없다(서버가 해시만 저장).
- 409 가 오면 다시 조회한 뒤 판단을 새로 한다. 같은 요청을 되풀이하지 않는다.
- 도구가 「연결할 수 없습니다」면 서버가 꺼진 것이다. 여기서 멈추고 서버를 켜 달라고 말한다.
