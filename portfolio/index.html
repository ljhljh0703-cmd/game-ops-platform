일곱 단계 · 사람이 정하는 곳 두 군데

  1. 디스코드 제보

    게임별 채널 글이나 /report. 같은 메시지는 한 번만 저장합니다.

  2. 분류 · 묶기

    제보 종류를 나누고, 비슷한 제보는 이슈 하나로 묶습니다.

    서버

  3. 게임별 슬랙 카드

    게임마다 채널과 봇 얼굴이 따로. 버튼으로 상태와 분류를 고칩니다.

    서버

  4. 피드백 보고서

    슬랙에 /피드백정리 한 줄. AI는 고르고 요약하고, 숫자는 서버 기록에서 채웁니다.

    AI · 서버

  5. 개발 지시서

    보고서 카드 버튼으로 게임 저장소에 깃허브 이슈를 만듭니다.

    사람 ① 넘길지

  6. 수정 · 합치기

    개발 AI가 고쳐 PR을 올리고, 사람이 읽고 합칩니다.

    사람 ② 합칠지

  7. 해결 · 답장

    서버가 20초마다 합쳐진 PR을 읽어 해결로 바꾸고 제보자에게 「고쳤어요」.

    서버

QA가 있는 팀을 위해 6과 7 사이에 「QA 확인 대기」를 두는 설정도 만들었습니다(사람 ③ 고쳐졌는지). 이 단계와 Jira 버그 티켓 연결은 시험으로만 확인했습니다.

QA가 먼저 묻는 네 가지를 미리 받습니다

버전 · 기기 · 재현 방법 · 스크린샷을 제보와 함께 받고, 빠진 것만 접수 답장에서 다시 묻습니다. QA 확인 단계와 Jira 버그 티켓도 붙일 수 있습니다(시험으로만 확인).

실제 게임사 팀이 써 본 적은 아직 없고, 제보가 몰리는 상황도 아직 겪지 않았습니다.

AI가 하는 일
  • 보고서에 넣을 이슈 고르기와 한 줄 요약
  • 개발 지시서를 읽고 게임 코드를 고쳐 PR 올리기 (사람이 돌림)
  • 분류 규칙 수정안 내기
서버가 기록대로 하는 일
  • 같은 문제 묶기, 제보 수 · 심각도 · 상태 채우기
  • AI가 낸 규칙 수정안을 평가 문장으로 다시 시험해 통과한 것만 반영
  • 합쳐진 PR을 읽어 해결로 바꾸고 제보자에게 답장
사람이 정하는 일
  • ① 보고서를 보고 개발 AI에게 넘길지
  • ② 고친 코드를 합칠지
  • ③ 정말 고쳐졌는지 (QA 확인 · 시험으로만 확인)

심각도와 보류는 사람이 언제든 바꾸고, 사람이 정한 심각도는 다음 제보가 덮어쓰지 못합니다. AI 도구 키로는 해결 · 보류를 누를 수 없고, 결제 · 크래시 분류를 빼거나 낮추는 규칙 수정은 서버가 거절합니다.

해결 버튼을 다시 정한 과정

2026-10-21 시연 흐름 점검

  1. 문제

    시연 단계를 하나씩 따라가 보니 코드를 고치기 전에 슬랙에서 [해결]을 누를 수 있었습니다.

    [해결] 버튼만
  2. 판단

    고친 PR을 사람이 합치는 순간을 해결로 보기로 했습니다. 서버가 게임 저장소를 20초마다 읽어 PR에 적힌 운영 이슈 번호를 찾습니다.

  3. 검증

    보석타워 저장소에서 PR #2를 합치자 운영 이슈 9가 해결로 바뀌고, 디스코드 제보 글에 「고쳤어요 · 이슈 #9」 답장이 달렸습니다.

  4. 결과

    해결은 고친 코드가 들어올 때 일어납니다. 코드 밖에서 고친 경우를 위해 슬랙 [해결] 버튼은 남겨 두었습니다.
